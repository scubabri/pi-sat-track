Hamlib/rigctl TCP — SDR++, remote rigctld, any net rigctl server.

How to start rigctld on the radio computer

Mac

Install: brew install hamlib · find port: ls /dev/cu.usbmodem*

rigctld -m 3085 -r /dev/cu.usbmodemXXXX -s 19200 -T 0.0.0.0 -t 4532

Background:

nohup rigctld -m 3085 -r /dev/cu.usbmodemXXXX -s 19200 -T 0.0.0.0 -t 4532 > ~/rigctld.log 2>&1 &

Windows

Install: Hamlib Windows build from github.com/Hamlib/Hamlib/releases · port: Device Manager (COMx)

rigctld.exe -m 3085 -r COM5 -s 19200 -T 0.0.0.0 -t 4532

Background (cmd, or PowerShell):

start /min rigctld.exe -m 3085 -r COM5 -s 19200 -T 0.0.0.0 -t 4532
Start-Process rigctld.exe -ArgumentList '-m 3085 -r COM5 -s 19200 -T 0.0.0.0 -t 4532' -WindowStyle Hidden

Linux (incl. Raspberry Pi)

Install: sudo apt install libhamlib-utils · find port: ls /dev/ttyACM*

rigctld -m 3085 -r /dev/ttyACM0 -s 19200 -T 0.0.0.0 -t 4532

Background:

nohup rigctld -m 3085 -r /dev/ttyACM0 -s 19200 -T 0.0.0.0 -t 4532 > ~/rigctld.log 2>&1 &

-m model (3085 IC-705, 3081 IC-9700; rigctl -l | grep 9700) · -r serial port · -s baud = radio CI-V USB baud · -T 0.0.0.0 listen on network · -t port = endpoint port (4532) · -vvvv verbose. rigctld has no daemon flag; for start-at-boot use a systemd service (Linux) or launchd agent (Mac).

Limits & stops

Never drive across this stop — tracking and rotator test go the long way instead.

When the selected sat drops below Min EL: Do nothing holds the LOS azimuth; Park sends the rotor to Park AZ/EL (if Antenna is on) and re-engages 5 min before the next AOS. Combine with the top-bar Auto Select button to also switch to the favorite with the soonest AOS.

Min EL applies to tracking and pass AOS/LOS. Antenna on → preposition 5 min before next AOS.

Device & test

Logging

Same report as the sidebar AMSAT Heard button (your callsign/grid, UTC time of the QSO), for the logged satellite. Sent at most once per pass, also counting a Heard you already sent with the button. Applies to the Log button and to WSJT-X QSOs logged for the selected satellite. Never delays the log.

Records are appended; header is written when the file is new. ~ = home of the user running pi-sat-track.

Multicast group: loopback is on, so apps on this Pi also receive it. TTL 1 = local subnet (WSJT-X default).

GridTracker2 / Log4OM 2 listen on 2237 (WSJT-X). Unicast IP, x.x.x.255 broadcast, or a multicast group such as 224.0.0.1 or 239.255.0.1 (enable multicast in the receiver with the same group + port). In Log4OM enable "Import QSO from JT Message #12" so SAT_NAME comes through. Plain ADIF: Log4OM ADIF inbound (2333) or GridTracker2 "Receive ADIF UDP Broadcasts".

WSJT-X listener

In WSJT-X Settings > Reporting set UDP Server to this Pi's IP and this port. QSOs are re-sent with PROP_MODE=SAT, SAT_NAME and tracker UL/DL frequencies through the Logging output above (only while the selected sat is up; otherwise unchanged). The listener only runs while both Radio and Antenna are on.

Listener off

KISS TNC

Only connects (and reconnects) while this is on. Turning it off closes the connection.

One row per TNC channel: Graywolf binds one channel per KISS TCP port; 9600 G3RUH needs Direwolf (MODEM 9600).

Satellite sends go out on a TX-capable connection whose speed matches the satellite (Per-satellite speed under Transmit); with no satellite, on the Default TX connection.

KISS: off

Graywolf / Direwolf setup

Graywolf (remote host or this Pi): Interfaces → KISS TNC → + Add Interface, Type TCP (server), listen 0.0.0.0:6700, Channel = your sat radio channel, Mode = Modem (Graywolf's modem keys the radio). Leave "Allow digipeater/beacon/iGate to transmit" alone (TNC mode only). Turn off Graywolf beacons / digipeater rules for the satellite channel. Graywolf drops a repeat of the same packet within 30 s. Graywolf binds one channel per KISS TCP port (e.g. 8001 = FLEX ch1 with TX, 8002 = VHF Dax 3 RX only): add one row per port. Graywolf only has 1200 AFSK / PSK modems.

Direwolf for 9600 G3RUH sats: MODEM 9600 on the 9600 channel and e.g. KISSPORT 8003; add a row with Speed 9600 G3RUH (see docs/APRS.md). KISS port (Advanced) is only for multi-channel Direwolf / multi-port TNCs. Bluetooth TNC (Mobilinkd, TH-D74/D75): pair once with bluetoothctl, then sudo rfcomm bind 0 <MAC> and pick Serial, /dev/rfcomm0.

Source = your Station callsign (no SSID unless set).

Transmit
Sending is never blocked by the selected satellite's elevation or mode.
Like UISS: To / Via form the header of every packet (CQ VIA ARISS). Change them per send in the APRS windows.

Empty = from the AMSAT digipeater list (ISS, IO-86, NO-44, SONATE-2 = 1200; CroCube, GRBBeta, KNACKSAT-2, KOSTKA, LASARsat, Marina = 9600), else the selected mode (9k6 / G3RUH = 9600), else 1200.

Resending the same position / UI text within 30 s appends “ #2”, “ #3”… so Graywolf (drops identical frames within 30 s) and digipeater dupe filters pass it. Messages are not changed.
Your packet heard back with a used (*) digipeater = digipeated; logged to ~/.rpitrack/aprs/digipeats.jsonl.
Copies of one packet (direct and via digipeaters, any connection) collapse into one ×N row; click it to see each path.

Header = CALL>To,Via (UISS style). APRS messages are sent without ack request (UISS default); no retries.
